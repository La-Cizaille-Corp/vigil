1. Ce qu'il faut vérifier

Pour une distribution, le paquet source : openssl, pas libssl3.

C'est elle qui est vérifiée ; latest : toujours la dernière.

Avec la version, l'actif est vérifié dans OSV.

À la place de l'écosystème : type, nom et version du paquet.

Pour un produit sans purl, vérifié dans la NVD : trouver son CPE.

Avec « Versions à partir de… ».

Aide : comment Vigil trouve les vulnérabilités

Un purl, ou un écosystème avec une version : l'actif est vérifié dans OSV. Si le purl porte une autre version que le champ Version, c'est le champ Version qui est vérifié. Pour une distribution, précisez sa version (Debian:12) et nommez le paquet source (openssl, pas libssl3). Le noyau Linux est un paquet comme un autre : linux dans Debian:12, kernel dans AlmaLinux:9, ou l'écosystème Linux pour le noyau officiel, avec sa version.

Un produit ou une technologie sans purl : un CPE, vérifié dans la NVD (« Trouver son CPE » sur la page Ajouter des actifs). Mettez « * » à la place de la version pour suivre le produit entier, et aussi à la place du produit pour suivre tout l'éditeur : cpe:2.3:*:fortinet:*:*:*:*:*:*:*:*:*.

Sans purl, CPE ni version, Vigil cherche le nom de l'actif dans les descriptions des CVE de la NVD : donnez-lui le nom employé par l'éditeur (« Ivanti Connect Secure », « FortiOS »). Moins précise, cette recherche donne des résultats à vérifier.

Version latest : l'actif est tenu à jour sur la dernière version publiée. Seules les vulnérabilités sans version corrigée connue sont signalées, et elles sont marquées corrigées dès que le correctif sort.
