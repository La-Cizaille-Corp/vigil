Détection des vulnérabilités

Renseignez un purl, ou un écosystème avec une version : l'actif est vérifié dans OSV. Si le purl porte une autre version que le champ Version, c'est le champ Version qui est vérifié. Pour une distribution, précisez sa version (Debian:12) et nommez le paquet source (openssl, pas libssl3). Pour un produit ou une technologie sans purl, renseignez un CPE : il est vérifié dans la NVD (pour le trouver : « Trouver son CPE » sur la page Inventaire ; mettez « * » à la place de la version pour suivre le produit entier, et aussi à la place du produit pour suivre tout l'éditeur : cpe:2.3:*:fortinet:*:*:*:*:*:*:*:*:*). Sans purl ni CPE, Vigil cherche le nom de l'actif dans les descriptions des CVE de la NVD : donnez-lui le nom employé par l'éditeur (« Ivanti Connect Secure », « FortiOS »). Moins précise, cette recherche donne des résultats à vérifier.

Le noyau Linux est un paquet comme un autre : linux dans Debian:12, kernel dans AlmaLinux:9, ou l'écosystème Linux pour le noyau officiel, avec sa version.

Version latest : l'actif est tenu à jour sur la dernière version publiée. Seules les vulnérabilités sans version corrigée connue sont signalées, et elles sont marquées corrigées dès que le correctif sort.

Période de suivi : par défaut, les 120 jours précédant l'ajout de l'actif, puis toutes les nouvelles vulnérabilités. Celles publiées avant ne sont signalées que si elles sont activement exploitées (CISA KEV). Videz la date pour suivre tout l'historique.
